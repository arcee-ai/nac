# Configured-local AX companion integration

This is test infrastructure. The ordinary product, its closed normal build input roster, all
public XCUI actions and Runner sandbox remain unchanged. Canonical lifetime,
freshness and refusal policy lives in the exact Q supplier's
startup_xctest/AX-WITNESS-CONTRACT.md. A private source nomination is not actual
native acceptance or permission to run another workflow.

The helper has two finite modes in separate processes. The existing metadata
observer keeps its original 50ms process/retirement loop. `--ax-witness` starts
one independent readonly AX companion for configuredLocal. No AX messaging is
added to metadata sampling. H's existing ci.run process owner supervises the
companion, and its own phase records the effective cap and elapsed interval.

Compile the helper with the complete list from `ci_startup.observer_sources`:

- H CIStartupObserver.swift and CIStartupAXWitness.swift.
- Q StartupAXGuard.swift and StartupAXReceipt.swift at immutable canonical paths.

The generated startup XCTest target must compile Q StartupJourneys.swift plus
those same two Q shared files. The ordinary native target is unchanged. The
project selection receipt hashes every selected source. Do not compile the
main helper file alone or extract/fork Q's policy into a runtime string.

The frozen config declares exact helper/support hashes, the parent PID, a nonce
and a private profile-relative receipt path outside HOME/store/raw evidence.
The original H work deadline minus its reserve is frozen before SDK compilation.
At start the companion fixes min(frozen deadline, now + existing 300s case cap).
Each sample is bounded to 1s total; each guard is bounded to 30s inside that
original case allowance. Private exact field text never enters export.

Parent readiness validates the helper kernel identity and initial receipt
before XCTest starts. Cleanup stops/drains/reaps the companion before app
settlement and profile deletion. Unknown companion ownership retains the
profile even if app settlement is positive. The .stop file is parent-only
cooperative termination, never a Runner request or product endpoint.

retain_ownership flag changes receipt retention only; default launches and
existing bounded teardown remain unchanged. A missing receipt refuses cleanup
qualification, and a receipt sink failure preserves an original helper error.

non-ready retiring state; a positively proved known-app ESRCH becomes retired.

fails. Parent custody remains live and bounded until stop. Final qualification
requires the original completed case proof plus independent exact app/engine
retirement from OwnerWitness; empty apps alone is never positive settlement.
