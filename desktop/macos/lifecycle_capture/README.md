# Private lifecycle composited-capture supplier

This is a source candidate for one separately Root-admitted experiment. It is
not wired into public workflows, not native acceptance, and not permission to
compile, run or merge. Root owns the independent source review and any later
compiler/SDK/hosted admission. Existing STOP345, original fixture restrictions,
spent attempts, public stacks and unrelated qualification defaults are unchanged.

P is exactly `4b7a1f3e0bf6175a77c5ebf627fe965860e99976`; the canonical six-file
lifecycle app, engine, packaged observer and journey imports remain unchanged.
H starts at `ebdbd340bdc1220318446180c0a0df579489392c`. The new controller must be
one clean child of that H. It accepts only its exact private branch, first manual
job, original producer/artifact/manifest, unspent three-case allocation and
literal queue-inclusive Root clock. No allocation, epoch or nonce is issued here.
The original sealed lifecycle package must already have been transferred and
verified by Root's producer/download owner. `verify_lifecycle_files` checks its
original ZIP, inventory, build receipts and P source. No normal role is rewritten.

`q_driver.py` is a distinct Q identity: its whole original P AST is retained,
with only two optional callbacks after confirming/reconfirming. All original
close/reopen, minimize/restore, document/incarnation, duplicate/Cancel, second
confirmation, Stop, store/transcript/goal/grant/replay and descendant assertions,
actions and finally owners remain. The frozen f902 transaction owners in
`transaction/` change only imports; they are private P12 identity adaptations,
not replacements for H's ordinary lifecycle defaults. `provenance.json` records
their origin. No SDK/AX helper selects another app or issues clicks/keys.

A private immutable global configuration covers three fresh per-case ports and
one real generated XCTest runner. One SDK build selects two named Swift inputs;
full actual compiler output is retained, including SDK-generated glue. There
are three serial selected test methods, three separate read-only external AX
companions and the original three Q drivers. Raw AX never runs in the sandboxed
XCTest process (actual03's AXWindows -25211 remains a genuine prior failure).
CFEqual root/sheet/button identities, kernel app/engine births, original binary
stamps, native document/confirmation, frame, focus and occluder samples bracket
six uncropped public `XCUIScreen.main.screenshot()` PNGs. No unknown AX result is
retried to obtain a positive; failure is sticky. Native/API shape and host/SDK
support remain unproved until separately admitted execution.

Notifications are hints only. Release1 permits the original journey to proceed;
release2 requires actual SDK success, selected-test attachments, public caption
and original PNG digest/source join, runner retirement and positive companion
settlement first. Both releases contain request/configuration/nonce/phase binding
and `capture_verified:false`; there is no live PNG-hash response channel.
After Q returns, its real before/after private fences join those actual collected
attachments. Only then can structural capture completeness be asserted. It still
requires review of the actual pixels and never claims paint or trusted-input
acceptance. A forged hint cannot substitute for a real result/owner proof.

All new processes use the maintained `ci.run` process-group/handle/drainer owner;
the original driver and native fixture owners remain unchanged. Recorded PIDs
are observations, not signal authority. Each accepted owner is attempted during
cleanup even when another fails; the original primary error survives. Unknown
runner/helper/native settlement prevents success and the next case. Cases are
reserved durably and serially; no interrupted or failed prefix grants reentry.
