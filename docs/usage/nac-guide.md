# NAC Guide

NAC Guide is release-local self-help, available as `$nac-help` in fresh
installations. Ask a normal product question such as “How do I add MCP?” or
“Where are my skills?” Primary direct, direct-with-orchestrator and orchestrator
agents receive a compact routing instruction. Coding requests that merely
mention NAC remain coding requests. A help request never authorizes executing
commands, changing settings, launching work or altering permissions.

## Sources and retrieval

The executable embeds a deterministic pack made from maintained NAC Markdown
documentation. It requires no checkout, internet, Exa key or manual skill
installation. `nac_guide` provides a bounded topic index/search, manifest and
section reads. Sources carry stable `document_id` and `section_id` values,
source paths, content digests and the pack fingerprint, alongside the installed
`product_version`, `build_id`, `track` and `source_revision`.
Readable excerpts appear in ordinary tool results. Answers cite those refs and
the installed version; no custom URL scheme or app bridge is required.

For offline use without starting a server, `nac-web guide --query skills`
searches the installed index. `nac-web guide skills` lists its sections and
`nac-web guide skills discovery` reads a bounded excerpt. Pass `--offset` with
the returned `next_offset` to continue a section. These commands write no
configuration, create no store and perform no network requests.

The installed pack is authoritative for installed behavior. Online main/latest
documentation can describe a different release and must be labeled separately.
Unknown topics and current configuration remain unknown. A supplied stale pack
fingerprint fails with a version mismatch; search the installed index again.
Restart/resume uses the current binary's immutable pack, with fresh identity in
each retrieval result. Old transcript excerpts remain historical evidence.

Guide retrieval runs in the harness, independent of Local, SSH or Podman
filesystem access. Managed binaries embed the same pack. That portability does
not prove backend infrastructure, network access, credentials or other tools are
available. Worker threads receive only selected skill preloads; they have no
general skill activation/catalog. A selected guide preload carries retrieval
instructions for its immutable references.

## Provenance and collisions

The name `nac-help` is reserved for the bundled first-party guide. Filesystem
definitions using that name, or names that extend its invocation with a space
or punctuation boundary, are skipped with a warning. Other skill names keep
their existing project-before-user precedence. The catalog and expanded guide
identify the bundled source. Project/user skill text cannot replace this source
or its embedded reference bytes. No writable cache or persistent guide database
is used. The external `nac-onboarding` helper keeps its existing use.

## Maintenance

NAC maintainers own the bundled router, registry, generator and release
packaging. Feature owners update the existing canonical docs with product
changes. Maintainers keep `scripts/nac-guide/sources.json`, which maps stable
document and section IDs to source headings. Preserve existing IDs when titles
change. Add or update representative grounding fixtures with behavior changes.
The source paths and headings must resolve; the generator checks Markdown links
and refuses unknown/missing sections, duplicate IDs and oversized inputs.

Run `make generate-nac-guide`, then `make test-nac-guide` and the focused Rust
guide/registry/prompt/runtime tests. `pack.json` is generated by that single
writer and must be committed with source changes. The drift gate is part of
`make test`. Build identity is compiled from the same shared identity owner as
the server. Release and managed-image builds embed the pack in the executable;
the packaging tests verify retrieval without a source checkout.
